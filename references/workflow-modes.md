# 工作模式与入口判定细则

> 配套主流程使用：回答「从哪一步开始、到哪一步结束」。
> **流程非固定**——步骤是模块，按需裁剪；但组合有硬约束（第四节，不得放宽）。

---

## 一、入口判定三步法

1. **看现状**：快速检查知识库是否已有体系——
   - 已整理信号：存在结构化目录（如 `01-XX` 系列板块）+ 各板块有 README（`00-README.md`）；
   - 未整理信号：条目散落、根目录堆积、命名随意；
2. **听指令**：分析用户表述，对照第五节「信号词对照表」匹配模式；
3. **确认后执行**（不猜）：用一句话复述理解，请用户确认；不确定时给出 2–3 个候选模式让用户选。

**确认话术示例**：

> 「我先确认一下：你这边的需求是【增量整理】——把最近新入库、还没归档的内容按现有目录体系归位，对吗？
> （我看了下知识库：已有 5 个板块的目录体系和 README，通常增量整理即可；如果你更想做一次整体重规划，告诉我。）」

---

## 二、五种模式的执行细节

### 模式 1 · 全流程（初次整理）

- **适用**：知识库无体系 / 散乱，需要从头建立；
- **步骤**：探查 → 定位与规划 → 目录体系与方案 → 执行 → 报告（完整主流程）；
- **产出**：存量画像 / 定位与规划 / 整理方案（拍板）/ 执行 / 执行报告。

### 模式 2 · 增量整理（高频常驻）

- **适用**：已有体系，新入库内容（微信转发文章等）堆在根目录或游离未归档；
- **步骤**：
  1. **增量探查**：只识别「未归档增量」+ 随手健康扫描（空壳目录、孤儿条目、明显错位）——**不重读全库**；已有体系直接沿用，不重做定位与目录设计；
  2. **简版方案**（确认门）：直接给「增量条目 → 目标目录分布」表（条目数 + 代表示例 + 去向），并附：
     - **新主题观察**（若有）：某主题积累 N 条无处置放 → 建议扩目录；
     - **历史错位建议**（若有）：顺带发现的历史遗留错位条目——默认**只列入建议、不动**；用户说「顺手一起归位」则并入方案；
  3. **执行**：只动增量（+用户确认的顺带项）；沿用核心规则；
  4. **报告**：增量版报告（入库条目数 / 去向分布 / 新主题观察 / 待人工）。
- **注意**：方案虽「简」，确认门不省——用户回复「开始 / 可以执行」后才动手。

### 模式 3 · 局部整理

- **适用**：只处理某个范围——某目录 / 某主题 / 某一批条目（如「把根目录的文章归档」）；
- **步骤**：与增量相同，但范围由用户指定（先说清「这次只处理 XX，其余不动」）；
- **注意**：范围界定要在确认话术中说清，执行时严格限定。

### 模式 4 · 单步 / 指定区段

- **适用**：用户只要其中某步或某几步；
- **常见请求与本步实现**：

  | 用户说 | 执行 |
  | --- | --- |
  | 「只盘点一下」 | 仅探查 → 存量画像（不方案、不执行） |
  | 「出个整理方案（先别执行）」 | 探查 → 方案 → 交付即停（等拍板后另行执行） |
  | 「重建/重设计目录体系」 | 探查 → 定位确认 → 目录体系方案 → 停（或按用户指令继续） |
  | 「把骨架建起来」 | 按用户给的/已确认的目录结构建骨架 + README |
  | 「补一下 README」 | 仅生成并落位 README 体系 |

- **注意**：单步执行时同样遵守相关硬约束（如「建骨架」前要有已确认的目录结构）。

### 模式 5 · 巡检（只诊断）

- **适用**：定期健康检查，**不看方案、不执行整理**；
- **检查项清单**：
  1. 未归档堆积（根目录 / 游离条目数量）；
  2. 空壳目录（内容已迁出或空置）；
  3. 孤儿条目（无法归入现有体系的主题）；
  4. README 完整性（各板块是否齐备、是否过期）；
  5. 命名偏差（不符合库内命名规范的条目）；
- **产出**：健康报告（各项检查结果 + 建议清单：是否需要一次增量整理、是否该扩目录）——报告即终点。

## 三、新主题观察机制（增量 / 局部 / 巡检中均适用）

- **触发**：某主题连续出现、积累到一定量级（参考线：≥5 条）且无法自然归入现有板块；
- **动作**：在方案（或报告）中主动提示：「『XX』类内容已积累 N 条且无处置放，建议新增目录『XX』/ 作为『YY』的二级目录——是否纳入本次（或列入待办）？」；
- **边界**：只建议、不代做决定；用户确认后才纳入方案执行。

---

## 四、组合硬约束（任何模式都不得放宽）

1. **执行前必须有已确认的方案**：全流程 = 完整方案；增量/局部 = 简版方案；单步「建骨架/迁移」= 已有确认过的目录结构；
2. **只移动、不删除**：删除类操作一律列入报告交由用户手动完成；
3. **不动原文**：只调整位置；
4. **异常不猜**：重名 / 归属不明 → 保持原位 + 上报；
5. **可逆留痕**：执行清单留档；
6. **确认门**：涉及创建 / 迁移的动作前，必须有用户的明确指令。

## 五、信号词对照表（供模式匹配）

| 模式 | 信号词（示例） |
| --- | --- |
| 全流程 | 整理知识库、知识库太乱、重新规划、重新整理、大扫除、重建体系 |
| 增量 | 新文章归档、把新入的整理下、又有文章要归、按老规矩归档、再整理一下、归下位、最近存的整理下 |
| 局部 | 把根目录的文章归档、XX 板块理一下、这几篇归档、XX 目录整理 |
| 单步 | 只盘点、只要方案、先别执行、补 README、建骨架、重设目录 |
| 巡检 | 健康检查、巡检、看看哪里乱、检查结构、体检 |

## 六、常见边界案例应对

| 案例 | 应对 |
| --- | --- |
| 用户已明确说了要从哪步开始 | 尊重用户指定；只做必要的合理性提示（如「你要直接执行归档——我先把去向清单列给你确认一下」） |
| 用户已有体系但要求全重来 | 确认意图（是嫌体系不好，还是只想归档增量？）；按确认结果走 |
| 用户想跳过确认门（「直接开始」） | 本技能的核心安全机制——可给最简形式（「以下 10 条去向，回复『可』即执行」），但不取消 |
| 增量中发现历史错位 | 记录 + 报告建议；用户要求「顺手」才一并纳入方案 |
| 模式判断拿不准 | 不猜——列 2–3 个候选让用户选 |
| 知识库同时存在「旧乱区」与「新增量」 | 建议先增量（低成本见效），并在报告中提示「旧区整理」可作为下次专项 |
