# 操作地图编制规范 v1

> 适用：ima 知识库批量整理类任务（编制方＝WorkBuddy/本 skill；执行方＝ima copilot 或人工）
> 来源：真实知识库整理案例（2026-10-11）——232 条存量、37 批、231/231 成功、ID 一致性 8/8 验证通过
> 配套脚本：`scripts/gen_migration_map.cjs`（按本规范生成地图与机器清单）

---

## 一、角色分工与事实基础

| 角色 | 职责 |
| --- | --- |
| **编制方（本 skill）** | 快照 → 逐条归类 → 操作地图（md）→ 机器清单（JSON）→ 验收核验 |
| **执行方（ima copilot / 人工）** | 按批次执行移动、按标准格式回执 |

**事实基础**（实证结论）：

1. ima 开放接口无"移动 / 删除 / 改名 / 建夹"能力（仅"新增 + 读取"）；
2. ima copilot 具备库内移动能力（案例：231/231 成功）；
3. 两侧 ID 体系同源：media_id / folder_id 逐条一致、跨迁移稳定——**可放心互传 ID**；
4. 删除类操作（清空壳、删条目）只能人工在客户端完成；
5. **上传格式限制（实测）**：ima **不支持上传 json 格式**（支持 md / csv / PDF / Word / PPT / Excel / TXT / 图片等）——交接材料须用 `.md`（地图）+ `.csv`（机器清单）；案例：某次整理中机器清单 json 上传失败，改用 CSV 交叉对齐后精确执行成功。

## 二、编制流程（五步·标准件）

1. **快照先行**：运行 `scripts/export_kb_snapshot.cjs`，产出含 media_id 的全量清单——
   命名：`{库名}-全量清单-{YYYYMMDD}.csv`，历史快照加后缀（如 `-迁移前`）；
2. **逐条归类**：产出 mapping 文件（`media_id → 目标代号`，见第四节），并做**全覆盖校验**（待迁条目数 = 各目标之和 + 不迁项）；
3. **生成操作地图（md 人读版）+ 机器清单（JSON）**：一条命令完成（`gen_migration_map.cjs`），两者同源同批；
4. **自检**：数量守恒、统计口径、批次条数锚点、截断唯一性；
5. **交付执行**：优先建议 ima copilot；执行前与用户确认批次顺序与收尾清单。

> **可选件**：小任务（≤15 条）可只出 md 地图，不强制 JSON 与快照。

## 三、操作地图格式规范

1. **头部**：用途行＋**统计口径说明**（如"239 条＝231 待迁＋7 README 不动＋1 待处理"）＋**目标代号表**（代号｜全称｜层级说明｜folder_id——全称仅在代号表出现一次）；
2. **源位置标题带基线数**：`## 源位置：根目录（现存 69 条：68 待迁＋1 README 不动）`；
3. **批次标题统一格式**：`### 批次 03 ｜ → 02S（01-本地专区）｜ 1 条`（代号＋简称；不写"XX 的子文件夹"类说明）；
4. **条目清单**：标题逐条、批内编号；**超长截断规则**——>60 字截断为"前 30 字 +「…」"（单字符省略号）；截断后必须仍唯一，否则自动加长或附注；
5. **执行说明**（六项约定）：
   - 移动规则、批次顺序；
   - 前缀匹配约定（含「…」条目按前缀匹配）；
   - **同名消歧约定**：出现完全同名条目时，必须附 media_id 或强制源位置限定；
   - **跳过回执格式**：`批次号｜条目标题（或 media_id）｜原因（缺失 / 多候选 / 其他）`；
   - **执行回执要求（必需）**：全部批次完成后须提供回执，含 ① 各批次成功 / 跳过数 ② 异常条目 ③ 执行后各目标目录计数——**必须写进地图，不依赖执行方主动性**（教训：两例实战的回执均系执行方自觉提供，换一个执行方可能就不给）；
   - 收尾清单处理；
6. **去向统计＋批次总览**（验收锚点，执行后逐项核对）；
7. **收尾清单**：删除类操作单列"需人工确认"，不进入自动批次。

**示例片段**：

````markdown
## 源位置：社区运营资料（现存 6 条：全部待迁）

### 批次 31 ｜ → 90（90-运营专区）｜ 6 条

将以下 6 条内容移动到「90-运营专区」：

1. 社区活动报备表.md
2. 社群账号搭建指南.md
……
````

## 四、输入文件格式（mapping / config）

### 1. mapping.json（逐条归类结果，编制方产出）

```json
{
  "wechatarticle_cls1_……_1234567890123456": "01",
  "markdown_a1b2c3d4e5f60718_……": "02S"
}
```

- 键＝**media_id**（原样字符串，禁截断 / 再编码）；值＝目标代号；
- 覆盖全部待迁条目；不迁移的条目放进 config 的 `skip`。

### 2. config.json（本次任务配置，编制方产出）

```json
{
  "kb_name": "示例知识库",
  "kb_id": "Ulshp……（原样）",
  "date": "20261011",
  "targets": {
    "01":  { "name": "01-行业趋势与研究", "folder_id": "folder_……", "note": "" },
    "02":  { "name": "02-城市-社区-政策", "folder_id": "folder_……", "note": "" },
    "02S": { "name": "01-本地专区", "folder_id": "folder_……", "note": "位于 02-城市-社区-政策 内" },
    "03":  { "name": "03-方法与实操", "folder_id": "folder_……", "note": "" },
    "03AI":{ "name": "01-AI应用实践", "folder_id": "folder_……", "note": "位于 03-方法与实操 内" }
  },
  "target_order": ["01", "02", "02S", "03", "03AI"],
  "src_order": ["根目录", "根目录 / 行业公众号"],
  "skip": [{ "media_id": "……", "title": "……", "reason": "内容违规无法查看" }],
  "cleanup_folders": ["行业公众号（含 4 个子文件夹）"]
}
```

- `folder_id` 从快照的文件夹行获取（`media_id` 即 folder_id）；
- `src_order` / `target_order` 可选（默认：源按快照出现顺序、目标按 targets 键顺序）；
- `cleanup_folders` 用于收尾清单展示。

## 五、机器清单规范（CSV + JSON）

由 `gen_migration_map.cjs` 生成**两个格式**，分工明确：

| 格式 | 命名 | 用途 |
| --- | --- | --- |
| **CSV（交接标准）** | `{库名}-迁移机器清单-{YYYYMMDD}.csv` | **交执行方使用**（ima 可上传）；列：批次 / 源位置 / 目标代号 / 目标目录 / folder_id / media_id / 标题 |
| JSON（编制方存档） | `{库名}-迁移机器清单-{YYYYMMDD}.json` | 编制方与脚本使用（结构化、批次嵌套）；⛔ **不作为交接材料**——ima 不支持上传 json |

JSON 结构如下（供存档与脚本读取）：

```json
{
  "kb_id": "（原样字符串）",
  "kb_name": "示例知识库",
  "generated_at": "2026-10-11T13:30:00+08:00",
  "snapshot_file": "…….csv",
  "targets": { "01": { "name": "01-行业趋势与研究", "folder_id": "folder_……" } },
  "batches": [
    { "batch": 1, "src": "根目录", "src_id": "", "target": "01", "item_count": 13,
      "items": [ { "media_id": "wechatarticle_……", "title": "……" } ] }
  ],
  "total_items": 231
}
```

- media_id / folder_id 一律**原样字符串**（含 `=` 结尾、`folder_` 前缀等，禁截断、去前缀、再编码）；
- 与 md 地图**同批次、同顺序**；执行方按 media_id 精确执行，标题仅作人工核对。

## 六、验收规范

1. **执行方回执**（地图「执行说明」第 6 条已强制要求，勿依赖执行方自觉）：按批报告成功数；有跳过/异常时使用第三节的标准格式；回执须含三要素——① 各批次成功 / 跳过数 ② 异常条目 ③ 执行后各目标目录计数；
2. **编制方核验**（建议全量）：重扫快照 + `scripts/compare_snapshots.cjs` 比对；
   - 守恒三项：**总量不变**、**各目标数 = 去向统计**、**源位置清零**；
3. 删除类操作永远走人工确认区，不进自动批次。

---

## 七、边界与注意事项

1. 小任务（≤15 条）可简化为"md 地图"（不强制 JSON 与快照）；
2. 快照与执行**尽量贴近**；若间隔超过一日或期间有内容变动，执行前重扫快照；
3. 位置表达互转：WorkBuddy `根目录 / A / B` ↔ copilot `(root)/A/B`（已验证无损）；
4. 编制方与执行方 ID 体系一致性，务必先验证再互信（验证方法见 `capability-notes.md`）。
